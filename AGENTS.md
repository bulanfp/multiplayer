# Project: Multiplayer

Nuxt 4 SPA built with the Pixel 3 design system.

## Stack

- **Framework**: Nuxt 4, Vue 3, TypeScript
- **Design system**: `@mekari/pixel3` (token 2.4, Enterprise theme via `setProductTheme("enterprise")` in `app/app.vue`)
- **Deployment**: Cloudflare Pages

## Pixel 3

**MANDATORY**: Before writing or editing any component, always call the Pixel skill & MCP first. Never guess props, tokens, or patterns.

## Architecture

Multiplayer (product name; earlier drafts called it Envoy): one shared space per company where people and AI agents work in groups, and you chat privately with agents. There are no projects and no direct messages between people. `README.md` covers setup, scripts, the project structure and editing the mock content; it deliberately doesn't explain the product.

- **Routes** live under `/w/[workspaceId]`, where there is a single workspace, the company (`central-perk`; `defaultWorkspace`): `chat/[agentId]/[[chatId]]` (an agent's chats), `c/[conversationId]` (a group), `c/new` (a group being started from New chat; `NEW_GROUP_SLUG` is reserved), `activity`, `library`, `todos`, `agents`, `agents/[agentId]`. `/` and `/w/[workspaceId]` redirect to Airene's chats (`homePath`). Activity and Todos are hidden from the rail (`RAIL_ITEMS` in `app/data/navigation.ts`) but their pages still work; the Chats badge counts unread messages (`chatUnreadCount`).
- **Shell:** a dark header (logo, search, profile) over a rounded light canvas with an 8px dark gutter on the left, right and bottom. As in Mekari ERP, the icon rail sits inside the canvas: a gray square on hover, and a filled brand-green icon on it when active. A Discord-style green marker on the canvas's left edge grows a little on hover and stands tall on the active item. The header search (`HeaderSearch`, ⌘K / Ctrl+K) opens `UniversalSearch`, adapted from Pixel's enterprise layout, over groups, agents, your agent chats and the Library. The profile's avatar has an online/offline dot (`usePresenceStore`), set from its menu. Chats (the `home` section in code) adds a fixed 240px submenu (`HomePanel`): a "Chats" header whose + opens New chat (`NewChatPicker`), then two collapsible sections, **Agents** (Airene first, then each agent you have chats with, once, by latest activity; `AgentMenuItem`) and **Groups** (the groups you're in, by name; `ConversationMenuItem`). Sections collapse via `SidebarSection` (state in `useSidebarSections`); collapsed, they keep only unread or open rows. Row names stay regular weight even when unread or open; the badge and the selected background show that. There is no group browser. Pinned groups (`pinnedAt`, `togglePin`) move to a Pinned section; hovering or focusing a group row swaps its emoji (or an unnamed group's faces) for the pin button. Other sections, Agents included, are full width.
- **State** is module-level `reactive` stores in `app/composables/use*Store.ts` (workspace, chat, activity, todos), seeded from `app/data/seed.ts`. The app is a client-only SPA (`ssr: false`), so singletons are safe and agent-reply timers can write to state without a component. No Pinia. A reload resets everything.
- **Mock content** is one marketing team's work in `app/data/central-perk.ts` (PT Central Perk Indonesia launching the Holiday Blend; helpers in `app/data/seed-helpers.ts`); agent keywords and consults in `app/data/agent-scripts.ts`; output content and versions in `app/data/output-templates.ts`. Use the relative time helpers in `app/data/time.ts`.
- **Two ways to talk to AI:** in **groups**, people and agents work together: you @mention an agent and it replies in the open. Every group includes Airene (`AIRENE_ID`; `createChannel` and the seed's `channel` helper add her). **New chat** (`NewChatPicker`, a Google Chat-style popover: an `MpInputTag` of picks over Agents (yours, as in the sidebar), People and More agents, then Start, which reads "Open group" when it would reopen one) decides by who you pick: one agent alone is a private chat (`newAgentChatRoute`); people, or more than one agent, make a group, with Airene locked in, so nothing starts with only people. A group opens as a draft (`newGroupRoute`, `c/new`) and is created by the first message (`createUnnamedGroup`); the same members as one of your unnamed groups open that group instead (`findUnnamedGroup`). Unnamed groups (`isUnnamed`) are titled after their members (`unnamedGroupTitle`: people by first name, then agents, Airene only when she's the only agent), show two faces (`GroupFaces`) where named groups show an emoji, and only their members see them (`channelsIn`). The header's pencil and the intro's "Name this group" open `RenameGroupModal` (`renameGroup`), which gives the group a name and emoji. New chat's "Create group" opens `CreateChannelModal` with the picks ticked (`useAppModals().groupPicks`): People first (you ticked and locked), then Agents (Airene ticked and locked); `createChannel` posts who was added, people first. In **agent chats**, you talk to one agent privately (`kind: "agent"`): each agent has its own page (`chat/[agentId]`) listing your chats with it (`AgentChatList`: Recent, This week, Older; a filled dot marks unread; a "New chat" row leads Recent only after you start one with New chat or Message, via `newAgentChatRoute`'s `?new=1`) beside the chat itself (`AgentChatView`, styled like Mekari's Airene chat: your bubbles on the right, replies as plain text under the agent's name, "Writing…" and Stop generating). A new chat shows the agent's animated greeting and is saved, titled from your first message, when you send (`createAgentChat`). Outputs from agent chats stay out of the Library until you **Share** them to a group: the group opens with the output quoted in its message box (`startShare`, `MessageComposer`'s `quote`), and sending records `Output.sharedThreadIds`. The Agents rail is a roster (a grid with Message on each card) and `agents/[agentId]` is a tabbed detail page (mock setup in `app/data/agent-profiles.ts`, seeded cost in `app/utils/agent-usage.ts`).
- **Agents consult agents:** an agent can bring others in. In an agent chat, any other agent you @mention is consulted; scripts can also list `consult` agents for an intent. The agent says "Let me check with …", each consulted agent answers in full (`Message.consultedBy`), and then the agent replies, starting "Thanks, …" (`respond` in `useChatStore`). Both chat views label each run of consulted answers "Messages from …" (`ConsultLabel`, `groupConsults`) and set them on a thin rule.
- **Groups:** the UI says "group", but the code still calls them channels (`kind: "channel"`, `channelsIn`, `CreateChannelModal`). Groups have a human name, an emoji and a URL slug; there is no "#". Unnamed groups have a generated slug and no emoji until someone names them. With no projects, groups from different campaigns share one list, so names say which campaign they're for ("Holiday Blend copy", "Ramadan 2027 planning").
- **Messages** are rendered as text and mention segments (`app/utils/mentions.ts`). Never use `v-html`. In groups, messages are bubbles: yours on the right with your photo, everyone else's on the left under their name, each with the corner by the photo pointed. Bubble colours tell who's talking: yours `background.brand` (here and in agent chats), people's `background.neutral.subtle.hovered`, agents' `background.airene`. Bubbles are at most 600px wide and agent-chat replies wrap at 680px, so long messages stay comfortable to read.

## Conventions

- Components are registered by filename only (`pathPrefix: false`), so every `.vue` filename must be unique. Import Pixel components from `@mekari/pixel3` and app files from `~/...` explicitly.
- Buttons are full pills, as in Mekari's enterprise designs: always pass `is-rounded` to `MpButton`, and to `MpModalCloseButton` along with `aria-label="Close"` (it passes both on to its own `MpButton`). Pixel's enterprise product theme only changes colours, not radius. The exception is the icon-only ghost buttons in sidebar section headers (search, +): they leave out `is-rounded`, so their hover is Pixel's rounded rectangle, not a circle.
- Text links are the enterprise green: use `text.selected`. Pixel's `text.link` stays dark blue (#165082) even in the enterprise theme. Pixel also colours `secondary` and `textLink` buttons with `text.link`; global rules in `app/app.vue` give secondary buttons a neutral outline (`text.default` label, `border.bold` border, as in Mekari's enterprise designs) and text-link buttons the green, so don't add colour classes to buttons.
- Modals pass `scroll-behavior="auto"`: a tall modal stops 80px from the window's top and bottom and its body scrolls. Tabs use Pixel's default colour (no `variant-color`), which follows the enterprise tokens; `green` uses a fixed palette green.
- Tables use `EnterpriseTable` (`app/components/table/`), adapted from Pixel's "enterprise data table" block: compact rows, columns you can resize and pin, a sticky header and pagination. Empty cells show "-". On index pages like the Library, the tabs (labels only, no counts) sit on top of the white container, and the toolbar above the table has a filter select on the left and search on the right, with 24px above and below it. Column labels are Pixel's default (sentence case, same size as the rows).
- `css()` takes static values only. Express variants with `data-*` attributes (`"&[data-active]": {...}`); put keyframes in `<style scoped>`.
- Pixel's PostCSS step only re-runs when a file Vite already watches changes. The `pixelCssOnNewFiles` plugin in `nuxt.config.ts` reloads Pixel's stylesheet when a file is added under `app/`; keep it.
- Motion stays subtle: unhurried (about 0.5–0.6s with an even ease in and out) and never a zoom. Side panels slide in from the right like a drawer (0.6s in, 0.5s out) while the conversation narrows alongside. The rail has no hover micro-interaction beyond its background wash. Always add a `_motionReduce` / `prefers-reduced-motion` fallback (see `SidePanelTransition`, the sidebar row fold). The one playful exception is the agent on a new chat's greeting (`AgentMascot`), which uses squash and stretch on a 6s loop. Airene hovers above her shadow, pops up and twirls round (as in Mekari Airene), dances and blinks while her sparkle twinkles. Other agents breathe, hop with a twist, lean and look left and right, blink and wiggle. Its icon is split into body, eyes and any loose part such as Airene's sparkle (`public/images/agents/parts/`, positions in `app/data/agent-mascots.ts`) by `scripts/split-agent-eyes.py`; run it after adding or changing an icon (needs Python 3 and Pillow).
- Run `pnpm lint` and `pnpm format:check` before handing off.

## Testing in a background browser tab

Pixel modals and popovers animate with animejs, which pauses while `document.hidden` is true. In a hidden or background tab a modal can look stuck open after it closed. That's the test environment, not an app bug.
